# 接口章节模板

## 文档结构

按接口数量与读者需要组合以下部分。

- 文档标题及版本。日期、适用系统与实现状态有依据时加入。
- 接口目录，列出分组、接口名称、请求方法、路径及目标页码或链接。
- 公共约定，集中说明基础地址、鉴权、编码、请求和响应的媒体类型、时间约定、公共错误模型。
- 按业务能力分组的接口正文。
- 用户要求的配置说明、枚举字典或实现差异附录。

公共约定应包含有效信息。待确认项目写明问题，避免填入假定规则。

## 单个接口

### 接口名称

保留用户指定的编号。名称应表达可执行操作或可查询资源。

### 接口说明

说明用途、调用前提与关键执行语义。

| 项目 | 内容 |
| --- | --- |
| 请求方式 | `GET`、`POST` 等项目实际方法 |
| 请求路径 | 项目实际路径，查询参数在参数表列出 |
| 请求类型 | 项目实际 Content-Type，适用时填写 |
| 应答类型 | 项目实际响应媒体类型 |

鉴权、基础地址等公共规则通过文内链接引用。接口特有覆盖规则在此写明。

### 请求参数

| 参数名 | 类型 | 必填 | 位置 | 说明 |
| --- | --- | --- | --- | --- |
| 字段名称 | string / integer / number / boolean / object / array | 是 / 否 / 条件必填 | path / query / header / body / form | 含义、限制、默认值或生效条件 |

对象先列父字段，再列子字段。数组标明元素类型，数组对象中的字段使用 `items[].id`。位置为 `body` 时还应确认实际编码。条件必填给出具体条件。

无业务参数时写明无需业务参数。公共请求头按公共约定处理。

### 请求示例

给出实际方法和路径，以及适用的请求头、请求体。示例使用脱敏或虚构值，保证请求参数表与示例一致。

下面是用于检验模板表达方式的虚构接口。实际文档应换成项目契约。

```http
POST /example/api/jobs HTTP/1.1
Host: api.example.com
Content-Type: application/json

{
  "externalId": "DEMO-001",
  "items": [
    {"id": 101}
  ]
}
```

真实接口使用表单或查询参数时，按其实际编码生成示例。可直接复制执行的命令仅在用户需要时提供。

### 应答参数

在表格前注明已确认的成功 HTTP 状态。对流式、文件或无响应体接口，说明响应头与实际返回形式。

| 字段路径 | 类型 | 返回条件 | 说明 |
| --- | --- | --- | --- |
| id | integer | 成功时返回 | 任务标识 |
| progress | object | 成功时返回 | 任务进度 |
| progress.completed | integer | 成功时返回 | 已完成数量 |
| items | array<object> | 成功时返回 | 明细集合，空集合的含义按契约说明 |
| items[].id | integer | 存在明细时返回 | 明细标识 |

以上字段属于虚构示例。实际表格展开所有已声明业务字段。可空字段的类型可写 `number / null`，并说明何时返回 null。字段可缺省、字段为 null、空数组三种情况分别按契约描述。

### 应答示例

```json
{
  "id": 2001,
  "progress": {
    "completed": 1
  },
  "items": [
    {
      "id": 101
    }
  ]
}
```

应答示例保留真实根结构。单对象、数组、包装对象按项目接口分别呈现。枚举取值和描述字段保持对应。

### 错误码

| HTTP 状态 | 业务错误码 | 含义或触发条件 | 调用方处理方式 |
| --- | --- | --- | --- |
| 以项目依据填写 | 以项目依据填写 | 具体可识别的失败条件 | 已确认的处理建议 |

采用旧式统一 HTTP 状态的系统，按实际状态说明。没有独立业务错误码时，记录实际失败响应结构。重试建议应依据操作的幂等与副作用语义。

### 业务说明

按接口需要补充幂等键、重复提交、受理与完成的区别、状态流转、顺序规则、部分成功、关联资源等。已有文档中的重要约束必须有明确落点。
