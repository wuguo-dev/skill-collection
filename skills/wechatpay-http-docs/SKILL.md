# 微信支付风格 HTTP 接口文档

将已有接口契约整理为面向对接开发者的 HTTP 文档，使用清晰的参数层级、完整示例与可导航的版面。

## 工作流程

1. 读取用户指定的现有文档与补充要求，确认输出格式、名称和位置。已有授权足够时直接制作。用户要求先确认时，先交付具体的章节与字段变更清单。
2. 整理接口清单及来源。对每个接口记录方法、路径、参数位置、编码、响应结构和实现状态。重排已有文档时，以既有契约为依据。核对实现或新增接口属于用户任务时，再读取相关源码、数据库或协议资料。
3. 按 [接口章节模板](references/endpoint-template.md) 组织正文。完成条件为每个原有接口、字段、示例和业务约束都有去向，移除项均能对应用户的明确要求。
4. 制作 PDF、网页或 Word 时读取 [排版规范](references/layout.md)。沿用用户指定的输出类型。PDF 采用可点击目录、接口书签、方法与路径栏、参数表和代码块。
5. 校验参数与示例，再执行输出格式对应的视觉检查。PDF 检查每页渲染、分页、目录链接、书签及页码。完成后给出文件链接，并说明仍待确认的契约事项。

## 契约处理

- 请求参数的名称、大小写、类型、位置、必填性和默认值均来自项目契约。采用现有路径前缀，路径规范化根据用户本次授权处理。
- 应答中的对象与数组展开到实际业务字段，使用 `items[].id` 这类完整路径。同名字段保留各自上下文。
- 字段说明包含适用的单位、枚举含义、空值条件、取值限制、时间格式和时区。依据缺失时写明待确认项，避免从一个示例值推导默认值或类型范围。
- 明确区分已实现行为、已确认的目标契约与待确认设计。格式重排保留原有实现状态说明。对于文档与实现差异，按用户要求放置差异说明。
- 鉴权方式、Content-Type、HTTP 状态码与业务错误码采用项目依据。微信支付页面提供章节与视觉参考，业务规则按当前项目资料编写。
- 以读者所需信息安排篇幅。部署信息、公共协议与通用约定集中说明，各接口说明其特有规则。

## 交付核验

- 对照源文档清点接口数量及方法、路径、参数、业务说明，确认范围完整。
- 解析每个标注为 JSON 的示例，校验类型与参数表一致。`true`、`false`、`null` 采用 JSON 字面量，数值和字符串保持契约类型。
- 核对成功应答、条件应答及错误示例各自适用条件。异步受理、执行完成、幂等复用等语义在业务规则中说明。
- 使用当前环境提供的文档/PDF 库与渲染工具。具体依赖路径通过工具或环境发现，保持作者脚本可配置。
- 导航目的地对应实际接口起始页，目录页码与页脚总页数一致。修改分页后重新校验导航。
